### I. The Pressure of Physical Limits: Repository Sustainability

During practice review, Johan articulated a decisive operational reality:
> *"what about filesize? git is limited to 2 gb afaik. so we have to gitignore the biggest filetypes, and where files are needed for the website, think of a more efficient system."*

Upon analyzing the directory tree and Git object database, the diagnosis was unequivocal:
- **Total Local Project Footprint:** ~2.15 GB.
- **The Core Bottleneck:** 153 uncompressed 48kHz 16-bit PCM `.wav` audio suites accounted for **1.73 GB** (80.5% of total project size).
- **Redundant Duplication:** In `gallery/assets/`, 34 uncompressed `.wav` files (~666 MB) were exact byte-for-byte duplicates of master files already housed within `works/` and `sketchbook/`.
- **Git Tracking Risk:** All 153 `.wav` files were actively tracked in Git index, placing any push or clone dangerously close to GitHub's 2.0 GB quota.

---

### II. The Strategic Solution: Dual-Tier Archival Architecture

Rather than destroying our uncompressed creative recordings or compromising on audio fidelity, Studio Anamnesis enacted an elegant **Dual-Tier Archival Architecture**:

1. **Tier 1 — Master Archival Inscriptions (Local Physical Storage):**
   - Uncompressed 48kHz 16-bit PCM master WAV recordings remain permanently preserved on local disk in their originating directories (`works/opus_XXX/` and `sketchbook/`).
   - The master recordings serve as the uncompressed studio master tape.
   - Comprehensive `.gitignore` rules (`*.wav`, `**/*.wav`, `*.raw`, `*.pcm`, `scratch/`) ensure these large binaries are permanently excluded from Git tracking, halting repository growth in its tracks.
   - Untracked all 153 historical `.wav` files from the Git index (`git rm --cached`) without removing the physical master files from local disk.

2. **Tier 2 — High-Fidelity Web Delivery Stream (Repository & Exhibition):**
   - Batch-converted all 37 gallery console suites, 4 iterative study audio samples, and 7 interactive chamber audio files into high-bitrate (192 kbps libmp3lame) MP3 streams.
   - **Size Reduction:** Average file size shrank from 22.0 MB to ~2.7 MB—an **87.5% reduction** in bandwidth and storage.
   - Total gallery audio assets dropped from ~666 MB to **106 MB**.
   - Universal browser compatibility: 100% native offline playback under `file:///` local protocols and GitHub Pages with zero external dependencies, no CDN requests, and instant playback startup.
   - Removed the 34 redundant `.wav` duplicate files from `gallery/assets/`.
