# THE STUDIO SKETCHBOOK
### The Laboratory of Fragments, Studies, and Productive Failures

> *"A practice produces paintings, conceptual works, performances, situations, texts, sound, code... But other artifacts are also part of the practice: studies, fragments, failed works, notes, failed attempts, private rituals. The distinction between a finished work and a supporting experiment is important."* — `notes/Artistic-Practice-Definition.md`

This directory is the studio's workbench. Unlike `works/`, which contains formal, numbered Opuses documented in the Catalog Raisonné, `sketchbook/` is where ideas are tested without the obligation to be great, finished, or public.

---

## Structure of the Sketchbook

- **`studies/`**: Quick prototypes, parameter sweeps, code fragments, audio sketches, and visual studies exploring an inquiry.
- **`failures/`**: Experiments that broke down, dissolved into noise, proved dead ends, or failed their intended hypothesis—preserved because mistakes reveal boundaries.

---

## Sketchbook Protocol

1. When testing a new idea, write a standalone script here (e.g. `sketchbook/studies/test_silicon_mandala.py`).
2. Run it, inspect the output, evaluate it against `practice/judgment.md`.
3. If it reveals genuine necessity, depth, and resistance, it can be developed into a finished Opus in `works/`.
4. If it fails or is uninspired, do not hide it—document what failed in `failures/` or leave it in `studies/` for future reference.
